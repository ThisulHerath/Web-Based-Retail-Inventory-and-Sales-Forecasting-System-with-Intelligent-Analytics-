# Assignment 03 Progress II - Execution Pack

## 1. Day-by-Day Task Board

### Day 1 - Module Completion Baseline
- Freeze scope to responsible modules only.
- Each member validates one end-to-end flow in assigned module.
- Confirm role restrictions and major navigation paths are functioning.
- Evidence to collect: feature checklist per module.

### Day 2 - Validation and Error Handling
- Apply backend request validation to all POST and PUT endpoints in responsible modules.
- Standardize API error shape and user-facing frontend error messages.
- Cover edge inputs for all critical forms.
- Evidence to collect: invalid input screenshots and API error response samples.

### Day 3 - UX Flow and UI Consistency
- Improve task flows for frequent actions (create sale, stock move, product create/edit).
- Add clear loading, empty, error, and success states.
- Align labels, spacing, and button/text conventions across pages.
- Evidence to collect: before/after UI screenshots and flow map.

### Day 4 - Testing and Basic Security
- Execute module-wise tests plus cross-cutting security tests.
- Verify authentication, authorization, and invalid token behavior.
- Capture and document expected vs actual outcomes.
- Evidence to collect: test run output and pass/fail matrix.

### Day 5 - Presentation Rehearsal and Packaging
- Run at least two timed rehearsals (target 18 minutes).
- Each member presents own component with one happy path and one edge case.
- Prepare fallback screenshots/videos if environment fails.
- Evidence to collect: rehearsal timings and final artifact checklist.

## 3. Rubric-to-Evidence Mapping

### Progress of responsible components (10)
- Evidence: implemented module features demonstrated live.
- Required: at least 75 percent of responsible features working.

### User experience (6)
- Evidence: intuitive task flow and meaningful feedback states.
- Required: clear navigation and efficient completion of top actions.

### UI consistency and standards (3)
- Evidence: consistent layout, labels, readability, and formatting.
- Required: same style and naming conventions across interfaces.

### Input validation and error handling (5)
- Evidence: frontend and backend validation + clear error messages.
- Required: invalid and edge inputs blocked with actionable feedback.

### Testing and basic security testing (4)
- Evidence: unit/integration/security tests with outcomes.
- Required: explain test design, expected result, actual result.

### Professionalism and time management (2)
- Evidence: punctual, prepared, and timed presentation.
- Required: under 20 minutes with smooth transitions.
